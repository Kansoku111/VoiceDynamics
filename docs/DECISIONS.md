## 2. 信号の流れと遅延

ゲート → （レベラー、初期オフ）→ コンプ → 補正ゲイン（15 msの時定数で平滑）→ True Peakリミッター。バイパス用に、同じ遅延をかけた原音の経路があり、10 msでクロスフェードする。バイパスは「入力を報告遅延だけ遅らせた音」とビット単位で一致する（試験済み）。

遅延は**設定によらず一定**で、DAWに報告する：48 kHzで319サンプル（6.65 ms）、44.1 kHzで6.69 ms、96 kHzで6.32 ms、192 kHzで6.16 ms。内訳は、ゲートの先読み3 ms（ゲートを開く判定は遅らせない入力で行い、音だけを3 ms遅らせる）＋リミッターの先読み3 ms＋True Peak検出器の遅れ16サンプル。報告した遅延と実際の遅延（インパルスの到着位置）は、22.05〜384 kHzの全サンプルレート、モノラル・ステレオ、32/64ビットで一致する。計画の「ゲートの先読みも同じ遅延の中で」は、ゲートがリミッターの前に直列に並ぶため別々の遅延として足した（合計は未決定項目の上限10 ms以内）。

## 3. 各段

**ゲート**（`src/dynamics.cpp`）：検出は低域カット（既定80 Hz、最小値20 Hzでオフ）をかけた信号の10 ms RMS（正弦波のピークが0 dBになるよう校正）。開く／閉じる閾値のヒステリシス（閉じる閾値は開く閾値より上にならない）、Hold、Attack、Release（時定数は90%到達時間で指定）、Range（−80 dBで完全ミュート）。既定は −42/−48 dB、Hold 120 ms、Attack 3 ms、Release 180 ms、Range −12 dB。

**レベラー**（初期オフ）：300 ms RMS、補正は±6 dBまで、Attack 0.8 s、Release 2 s、ゲートが閉じている間と −65 dB未満では凍結。基準レベル既定 −24 dB、Ratio 1.5。

**コンプ**：フィードフォワード、2 ms RMS検出、ステレオはMaxでリンク、dB領域のソフトニー（Giannoulis）、分岐型のAttack/Release平滑。既定は Threshold −24 dB、3:1、Attack 10 ms、Release 150 ms、Knee 6 dB。

**リミッター**（`src/limiter.cpp`）：オーバーサンプリングしたピークから、サンプルごとに「許される最大ゲイン」を求め、先読み3 msの**スライディング最小値**（単調デック）を同じ長さの**移動平均**でなめらかにする。この構造では、ゲイン ≤ 許される最大ゲイン が全サンプルで成り立つ。戻り（Release）だけを遅くし、dB領域で、ゲインリダクションが深いほど長くする（× (1 + 0.125·|GR|)）。内部の上限は設定値より **0.1 dB低く**取る（`GuardDb`）。

True Peak検出器：Kaiserの窓つきsinc、位相あたり64タップ、β=9、各位相のDCゲインを1に正規化。倍率は44.1/48 kHzで16倍、96 kHzで8倍、176.4/192 kHzで4倍、それ以上で2倍。局所最大にフィルターの絶対値和の上限（λ）を掛けても閾値に届かない区間はフィルターを省略する（結果は同じ）。

**True Peak上限の保証範囲**：試験したすべての信号で、出力のTrue Peak（独立した16倍・128タップの基準で測定）は上限以下だった。試験の範囲：声の素材（実バイナリで13種の条件）、サンプルレートの 0.43倍以下の正弦波（位相の飛びあり、フルスケール）、クリップした正弦波、0.42倍で帯域制限したノイズ（+4 dBFS）、単発のインパルス（44.1/48/96 kHz）。上限との差の最大は −0.0204 dB（DSP試験）、−0.0999 dB（学習試験で実際のリミッターが働いた例）。**ただし、サンプルレートの0.43倍を超えるフルスケールの成分（ナイキスト周波数の交互信号など）では、上限を最大約0.85 dB超える**（情報として出力。合格条件にはしていない）。声の素材では起こらない。Taps 32→64、倍率 8→16に増やして、以前の約1.9 dB超過から改善した。

## 4. 測定（BS.1770-5）

- K特性：高域シェルフと2次ハイパスの係数を、サンプルレートごとに libebur128 と同じ導出式から計算する（コードは写していない）。48 kHzでITU表の値と一致（試験済み）。
- ブロック：400 ms、75%重なり。絶対ゲート −70 LUFS、相対ゲート −10 LU。LRAは Tech 3342（相対ゲート −20 LU、10/95パーセンタイル）。
- Momentary / Short-term は10 msの区間ごとに更新するので、Tech 3341の20 msのずれの試験（13・14）ができる。ストリーミングのメーターは0.01 LUのヒストグラムで集計する（表示用。この量子化で独立実装との差が最大0.01 LU）。**解析は、ブロックのパワーの一覧から厳密にゲートをかけて積分する**。
- モノラル：1ch（重み1、既定）か、デュアルモノ（重み2 = +3.01 dB）。
- 適合試験：Tech 3341 の試験 1〜5、9〜14（M/S/I、最大値）、15〜23（True Peak）、Tech 3342 のLRA試験 1〜4を、自作の試験信号で、44.1/48/96 kHzについて実施（126項目、すべて合格）。**試験 6（5.1ch）は対象外（モノラル・ステレオのみ）、7・8（実際の番組素材）はEBUの素材を使えないため、自作の声らしい素材と、独立実装のPython（`tools/crosscheck.py`、ITU表の係数）との比較で代えた**（差は最大0.0103 LU）。

## 5. 再生学習（主方式）

- 流れ：［学習開始］→ 再生 → ［学習終了］（または「停止で学習を終える」）。基準は**プラグインに実際に入ってくる音**。ゲート／レベラー／コンプを通った後、補正ゲインより前の信号を使う。
- 音声スレッド（`Learner::block`）がすること：状態の読み取り、位置の比較、FIFOへの書き込み（`memcpy`）だけ。確保・ロック・ファイル操作はしない（実バイナリのIAT差し替えで、ヒープ・ロック・待機・ファイル・ウィンドウ操作が0回であることを確認）。
- FIFOは学習開始時（UIスレッド）に 2^21フレーム×2ch（16 MB）を確保する。プラグインを非アクティブにしたとき、学習中でなければ解放する。
- バックグラウンドのスレッドが、FIFOから取り出して**メモリーに溜め**（256kフレームのかたまりに分け、上限3 GB。約2時間のステレオ48 kHz）、同時にBS.1770のブロックのパワーとTrue Peakを測る。一時ファイルは使わない（確保の失敗を避けるため上限を設けた。上限を超えたら警告して後半を記録しない）。
- 終了後：`solveGain`（`src/analyzer.cpp`）。まずリミッターなしの補正ゲインをブロックのパワーから**厳密に**求める。それでリミッターが働かない（ピーク+ゲイン ≤ 上限 −ガード）なら、その値が答え（リミッター0回）。働くときは、溜めた音にゲインと**プラグインと同じリミッターのコード**を当てて測り直すセカント法で、許容0.03 LUまで詰める（通常2〜4回）。誤差が0.1 LUを超えたら「目標に届かない」（上限が低すぎる、目標が高すぎるなど）。
- 警告（保存する）：途中から再生（開始位置が0.25秒より後）、巻き戻し、早送り、取りこぼし、学習中の設定変更（ゲート/レベラー/コンプ。学習開始時のハッシュと比べる）、サンプルレートの変更、ホストが再生位置を教えない、記憶の上限超え。位置はホストの `projectTimeSamples` と、前のブロックの終わりとの比較で見る（±2サンプルを超えると飛びと判定）。
- 再生の判定：`kPlaying`が立っているとき、または書き出し（`kOffline`）のときだけ記録する。ホストがProcessContextを渡さないときは再生中とみなし、警告を出す。
- 書き出し（オフライン）モードでだけ、FIFOがいっぱいのとき最大2秒待つ（取りこぼしを避ける。リアルタイムでは待たない）。
- 結果の適用：バックグラウンドのスレッドが完了時にコールバックで結果を受け取り、補正ゲインを原子変数に置く（音声スレッドが次のブロックで読む）。**画面を開いていなくても**適用される。
- 状態：待機中、記録中、計算中、完了、失敗。失敗は理由つき（音が入ってこなかった、など）。取り消しは、どの状態からでも戻れる。

### 予測の定義と誤差

予測（`MRecPred`）は、補正ゲイン（自動）だけを足した出力のLUFS-I。**手動の微調整は含めない**（微調整は学習し直さずに足せるので）。実測との差は、試験（13条件、44.1〜384 kHz、モノラル・ステレオ、32/64ビット）で最大0.027 LU。主な原因は、400 msブロックの格子の位置が、学習時（ゲートの先読みぶん遅れた音）と書き出し後のファイル（ホストの遅延補正後）とで数サンプルから数十サンプルずれることによるゲートの違いで、避けられない。許容0.1 LUには余裕がある。

### 結果が古いかの判定

`analysisHash`：ゲート・レベラー・コンプの全設定、リミッターのオン/オフ・上限・Release、目標、モノラルの測り方、チャンネル数。含めないもの：微調整、補正ゲイン（自動）のオン/オフ、バイパス、GR警告の値、停止で学習を終える。含めないものを変えても「設定が変わりました」にはならない（試験済み）。

## 6. WAV解析（補助）

`vd_dsp` の `analyzeFile`：WAV（PCM 8/16/24/32ビット、float 32/64ビット、EXTENSIBLE）を読み、再生時と同じコードでゲート・レベラー・コンプを通し、同じ `solveGain` を使う。サンプルレートがプロジェクトと違うWAVは断る（リサンプルしない）。チャンネル数はバスに合わせる（モノラル→ステレオは複製、ステレオ→モノラルは平均）。結果は再生学習と同じ形で保存する（「WAV」と表示）。画面にドロップするか、ボタンで選ぶ。ホストによってはドロップが届かない（未確認）。

## 7. 画面（Win32 + GDI+、JUCEなし）

1画面（960×824、75〜125%の拡大）。上段：再生学習の操作と状態、学習結果。中段：出力のラウドネス（Momentary/Short-term/Integrated。目標との差が±1 LU以内ならIntegratedを緑）、True Peak、ゲイン変化の履歴（約6秒）。下段：ゲート、コンプ、レベラー、リミッター、目標と出力。スライダーは数値入力もできる（Enterで確定、Escで取り消し）。表示は、メーターの世代が変わっていれば「再生中」、そうでなければ「再生を待っています」を判断する。

## 9. 既知の制限

- 0.43 fs以上のフルスケール成分でTrue Peak上限を最大約0.85 dB超える（3節）。
- 学習はメモリー上限3 GB（約2時間のステレオ）まで。超えたら警告。
- 学習中にプラグインを非アクティブにしても学習は続く（ホストが書き出しの前後でactive/inactiveを切り替えることがあるため）。ただしサンプルレートやバスの変更は警告になる。
- WAV解析はサンプルレートの変換をしない。
- 予測は微調整を含まない（微調整を大きくしてリミッターに当たると、実際の音量は予測とずれる）。

## 11. 0.2.0（2026-10-22）の変更

- **画面をAdobe Auditionの「ダイナミクス」に寄せた**（ユーザーの指示）。暗い配色、セクションごとのチェックボックス、ノブと青い数値、ゲート｜コンプレッサー｜レベラー＋リミッターの3列。Auditionのエキスパンダーの位置にはレベラーを置いた（依頼者はエキスパンダーを使わないため）。目標ラウドネスと学習は上段の1枚にまとめた。ノブは上または右へのドラッグで上がる（180 px で全範囲、Shiftで1/10）。クリックで値は跳ばない。
- **目標を変えたら自動で合わせ直す**。学習が終わった後も記録した音（補正ゲインより前の音）を保持し、目標・リミッター・モノラルの測り方だけが変わったときは、値が0.4秒止まってから記録で解き直す（再生不要）。ゲート・レベラー・コンプが変わったときは記録が使えないので、従来どおり「設定が変わりました」で学習し直しを求める。記録は取り消し・結果を消す・新しい学習・プラグインの無効化（setActive(false)）で解放される。曲を開き直した後は記録がないので、自動の解き直しはできない。
- パラメーターID・状態の形式は0.1.0から変更なし（状態の互換性あり）。
- 学習の終了後に下端の案内が「計算しています」のまま残る表示の不具合を直した。
